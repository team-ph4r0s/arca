# Arca 0.8.1 — Pharos

## Русский

Команда **Pharos** выпускает Arca 0.8.1. Это выпуск укрепления: путь стерильной копии, мосты к платформам, проверки в CI и удобство просмотра на Android. Номер ABI поднят до **9**.

**Стерильная копия.**
* Копия документа, открытого паролем (или встроенным паролем Excel), делается только с согласия читателя: без флага `ALLOW_DECRYPTED_COPY` гость отвечает новым статусом `DECRYPTED_COPY_REFUSED` (в движке `Status::DecryptedCopyRefused = 15`). На Android экран копии предупреждает, что копия не будет зашифрована, и без галочки согласия кнопка недоступна; на iOS то же спрашивается в окне. У сохранённой копии предупреждение повторяется.
* Хост больше не верит гостю на слово: готовую копию он заново прогоняет рентгеном в **новой** песочнице. Копия выдаётся, только если формат совпал с заявленным, нет активного и удалённого содержимого, а вердикт `Clean` (или `Unverified` для непрочитанной части). Список запрещённых частей расширен (`customUI`, `externalLinks`, `connections.xml`, веб-расширения, Basic и сценарии ODF); в PDF-копии запрещены `/JavaScript`, `/JS`, `/Launch`, `/OpenAction`, `/AA`, вложенные файлы, `/RichMedia` и `/XFA`, в том числе записанные через `#xx`. Изменение поведения: копия xlsx с диалоговыми листами Excel 5 теперь не выдаётся. Стерилизация стала дороже на один рентген копии.
* PDF, у которого ключ `/Encrypt` записан через экранирование (`/Encr#79pt`), теперь открывается паролем, как в любом читателе PDF. Раньше такой файл оставался нерасшифрованным.

**Мосты к платформам.**
* C ABI (iOS): `NULL` с ненулевой длиной и длина больше `isize::MAX` — ошибка `BadArgument` во всех экспортах; функции, открывавшие файлы по пути, удалены (только дескрипторы); новый экспорт `arca_abi_version()`. Приложение сверяет версию ABI при запуске, открывает файл само (`O_NOFOLLOW`, `fstat`, только обычный файл) и стирает байты пароля после вызова.
* Android: сервис песочницы отвечает только своему приложению (сверка uid); JNI отклоняет запись больше 64 КиБ вместо того, чтобы молча её обрезать. Приложение принимает документы только по адресам `content://`: приём `file://` с проверкой пути удалён.
* iOS: ссылку из документа теперь можно открыть. Сначала показывается полный адрес и кнопка «Копировать адрес»; в Safari открываются только `http` и `https`, остальные схемы можно лишь скопировать, как на Android.

**Android.**
* Режим «Страницами» показывает весь документ одной лентой: страницы рисуются по мере прокрутки, дальние отпускаются из памяти. Режим «По одной странице» остался. Страница, запрошенная во время отрисовки другой, больше не теряется; неудачная страница показывается с кнопкой «Повторить».
* Кнопка «Поделиться документом» на экране отчёта (без копий, с одноразовым разрешением на чтение) и «Поделиться стерильной копией» после сохранения. Для документа с активным содержимым — предупреждение, что получатель не защищён Arca.
* У каждой категории находок есть пояснение «Чем это опасно» и «Что делать», у каждой находки — «Что сделала Arca». Плитки счётчиков выровнены.
* Навигация по слайдам стрелками, экран «О проекте» показывает SHA-256 сертификата подписи релизов.

**Проверки и сборка.**
* Десять новых целей фаззинга: RTF, DOC, XLS, PPT, ODF, MSG, VSD, формулы, числовые форматы и текст, у каждой свои затравки и словарь; вне PR CI собирает отчёт покрытия.
* Тесты криптографии на векторах из самих стандартов (FIPS 197, SP 800-38A, FIPS 180-4, RFC 1321, RFC 6229).
* Релиз подписывается только после зелёного `ci` на том же коммите (задание `ci-passed`); NDK, nightly для фаззинга, XcodeGen и образы проверки воспроизводимости закреплены; удаление старых релизов вынесено в ручной `prune-releases`.
* `build-apk.sh` учитывает `ARCA_VERSION_NAME` и `ARCA_VERSION_CODE`. `check-unsafe.sh` проверяет C-файлы по всему репозиторию, ищет заглушки во всех языках и падает, если git недоступен. Тесты с настоящим гостем без него помечаются как пропущенные, а не проходят молча; host-test не оставляет копий документов во временном каталоге.

**Документация.** Ссылки ведут на `team-ph4r0s/arca`; README и модель угроз говорят только то, что делает код (Safe Rust в парсерах и ядре, `unsafe` в двух мостах; нет разрешения `INTERNET`); `SECURITY.md` с поддерживаемыми версиями и сроками ответа; политика веток и тегов в `RELEASING.md`; план распространения через F-Droid, Google Play и App Store (`docs/DISTRIBUTION.md`).

**Чего этот выпуск не делает.** Сборка и тесты прошли в `arca-dev` и в CI; на телефоне и на iPhone выпуск не запускался. Руками нужно проверить: ленту страниц и меню «Поделиться» на Android, работу сервиса песочницы с проверкой uid в настоящем изолированном процессе, окно согласия и ссылки на iOS. Зашифрованный ODF и RC4 в старых DOC/XLS/PPT по-прежнему не открываются.

## English

Team **Pharos** releases Arca 0.8.1, a hardening release: the sterile copy path, the bridges to the platforms, the CI gates and the Android viewer. The ABI is now version **9**.

**Sterile copy.**
* A copy of a document opened with a password (or with Excel's built-in one) is made only with the reader's consent: without the `ALLOW_DECRYPTED_COPY` flag the guest answers with the new status `DECRYPTED_COPY_REFUSED` (`Status::DecryptedCopyRefused = 15` in the engine). On Android the copy screen says the copy will not be encrypted and keeps the button disabled until the consent box is ticked; iOS asks in an alert. The saved copy repeats the warning.
* The host no longer takes the guest's word for it: it X-rays every finished copy again in a **fresh** sandbox. The copy is handed out only if its format matches, it has no active or remote content, and the verdict is `Clean` (or `Unverified` for a part that was not read). More parts are forbidden (`customUI`, `externalLinks`, `connections.xml`, web extensions, ODF Basic and scripts); a PDF copy may not contain `/JavaScript`, `/JS`, `/Launch`, `/OpenAction`, `/AA`, embedded files, `/RichMedia` or `/XFA`, also when written with `#xx` escapes. Behaviour change: a copy of an xlsx with Excel 5 dialog sheets is no longer handed out. Sanitizing now costs one more X-ray of the copy.
* A PDF whose `/Encrypt` key is written with escapes (`/Encr#79pt`) now opens with its password, as in any PDF reader. It used to stay encrypted.

**Bridges to the platforms.**
* C ABI (iOS): a `NULL` pointer with a non-zero length and a length over `isize::MAX` are `BadArgument` in every export; the functions that opened files by path are gone (file descriptors only); new export `arca_abi_version()`. The app checks the ABI version at start, opens the file itself (`O_NOFOLLOW`, `fstat`, regular files only) and wipes the password bytes after the call.
* Android: the sandbox service answers only its own app (uid check); JNI refuses a record over 64 KiB instead of silently truncating it. The app accepts documents from `content://` addresses only; accepting `file://` with a path check is gone.
* iOS: a link in a document can now be opened. The full address and a "Copy address" button come first; only `http` and `https` open in Safari, other schemes can only be copied, as on Android.

**Android.**
* The "Pages" mode shows the whole document as one strip: pages are drawn as they scroll into view and far ones are released from memory. The one-page mode is still there. A page asked for while another is being drawn is no longer lost; a page that failed shows a "Retry" button.
* "Share document" on the report screen (no copies, a one-time read grant) and "Share sterile copy" after saving. For a document with active content a warning says the recipient is not protected by Arca.
* Every category of findings explains why it is dangerous and what to do; every finding says what Arca did. The counter tiles are aligned.
* Arrow navigation between slides; the About screen shows the SHA-256 of the release signing certificate.

**Checks and build.**
* Ten new fuzz targets: RTF, DOC, XLS, PPT, ODF, MSG, VSD, formulas, number formats and plain text, each with its own seeds and dictionary; outside pull requests CI also produces a coverage report.
* Cryptography is tested with the vectors from the standards themselves (FIPS 197, SP 800-38A, FIPS 180-4, RFC 1321, RFC 6229).
* A release is signed only after `ci` is green on the same commit (job `ci-passed`); the NDK, the fuzzing nightly, XcodeGen and the reproducibility images are pinned; pruning old releases moved to the manual `prune-releases` workflow.
* `build-apk.sh` honours `ARCA_VERSION_NAME` and `ARCA_VERSION_CODE`. `check-unsafe.sh` checks C files across the whole repository, finds placeholder comments in every language and fails when git is not available. Tests that need the real guest are reported as ignored without it instead of passing silently; host-test leaves no copies of documents in the temporary directory.

**Documentation.** Links point to `team-ph4r0s/arca`; the README and the threat model claim only what the code does (Safe Rust in the parsers and the core, `unsafe` in the two bridges; no `INTERNET` permission); `SECURITY.md` lists supported versions and response times; the branch and tag policy is in `RELEASING.md`; a distribution plan for F-Droid, Google Play and the App Store is in `docs/DISTRIBUTION.md`.

**What this release does not do.** It was built and tested in `arca-dev` and in CI; it was not run on a phone or an iPhone. Still to be checked by hand: the page strip and the share menu on Android, the sandbox service with the uid check in a real isolated process, the consent alert and links on iOS. Encrypted ODF and RC4 in the old DOC/XLS/PPT are still not opened.
