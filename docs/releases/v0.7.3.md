# Arca 0.7.3 — Pharos

## Русский

Команда **Pharos** выпускает Arca 0.7.3: всё, что обещала 0.7.2, теперь в одном выпуске и проверено сборкой.

**Таблицы Word.** Заливка отдельных ячеек (`w:shd` в `w:tcPr`) и вертикальное объединение (`w:vMerge`) теперь доходят до экрана на Android и iOS. Цвет заливки задаёт сам документ, текст в ячейке остаётся читаемым на любой заливке в светлой и тёмной теме. Собственная подсветка текста (`w:shd` в абзаце или прогоне) ячейку не красит. Ячейка, покрытая вертикальным объединением, показывается пустой, того же цвета, что и верхняя.

**iOS собирается в CI.** Сборка iOS в 0.7.2 не запускалась: GitHub перестал принимать образ macOS 14. Теперь используется macOS 15; сборка, Swift-тесты на симуляторе и упаковка `.ipa` проходят, а `arca-0.7.3-ios.ipa`, сборка для симулятора и `ArcaCore.xcframework.zip` с контрольными суммами SHA-256 прикрепляются к релизу вместе с APK.

**Фаззер `wire` снова зелёный.** Проверка «значение после декодирования и повторного кодирования то же самое» падала на странице, у которой гость оставил размер не числом (`NaN != NaN`). Теперь значения сравниваются побайтово. На деле пользователей это не затрагивало: запись JSON заменяет не-числа нулём. Входные данные, на которых фаззер упал, сохранены как обычный тест (`crates/arca-engine/tests/wire_regression.rs`).

**Гость не может остановить приложение размером картинки.** Если гость сообщал ширину и высоту картинки по `u32::MAX`, произведение `ширина × высота × 4` переполняло `u64`, и хост падал (проверки переполнения в выпускаемых сборках включены). Теперь произведение проверяется, а такая картинка отклоняется как ошибка длины. Нашёл фаззер `wire` в CI, регрессионный тест в `crates/arca-engine/tests/wire_regression.rs`.

**Прочее.** Всё из 0.7.2 остаётся: подробный статический разбор макросов («Подробнее»), режим «Страницами» и настоящие цифры песочницы на iOS, релиз как Latest, очистка старых релизов и тегов ниже v0.3.0.

## English

Team **Pharos** releases Arca 0.7.3: everything 0.7.2 promised, now in one release and checked by builds.

**Word tables.** The fill of single cells (`w:shd` in `w:tcPr`) and vertical merging (`w:vMerge`) now reach the screen on Android and iOS. The document sets the fill colour; the text in a cell stays readable on any fill, in the light and the dark theme. A text highlight of its own (`w:shd` in a paragraph or a run) does not colour the cell. A cell covered by a vertical merge is shown empty, in the colour of the cell above it.

**iOS builds in CI.** The iOS build did not run for 0.7.2: GitHub stopped accepting the macOS 14 image. It now uses macOS 15; the build, the Swift tests on a Simulator and the packing of the `.ipa` pass, and `arca-0.7.3-ios.ipa`, the Simulator build and `ArcaCore.xcframework.zip`, each with its SHA-256, are attached to the release next to the APK.

**The `wire` fuzzer is green again.** The check "a value decoded and encoded again is the same value" failed on a page whose size the guest left as not-a-number (`NaN != NaN`). Values are now compared byte by byte. Users were never affected: the JSON writer turns a not-a-number into zero. The input that made the fuzzer fail is kept as an ordinary test (`crates/arca-engine/tests/wire_regression.rs`).

**A guest cannot stop the app with a picture size.** A guest that stated a width and height of `u32::MAX` made `width × height × 4` overflow `u64`, and the host panicked (overflow checks are on in the shipped builds). The product is checked now, and such a picture is refused as a length error. Found by the `wire` fuzzer in CI; the regression test is in `crates/arca-engine/tests/wire_regression.rs`.

**The rest.** Everything from 0.7.2 stays: the detailed static analysis of macros ("More"), the "Pages" mode and real sandbox figures on iOS, the release as Latest, and the clean-up of releases and tags below v0.3.0.
