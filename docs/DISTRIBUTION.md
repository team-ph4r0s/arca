# Распространение Arca: план для F-Droid, Google Play и App Store

Состояние на 0.8.1: Android-пакет публикуется только в GitHub Releases (подписанный APK, сертификат
`3b3b819d…737e`, см. README), iOS-сборка — только для симулятора и ad-hoc. Этот документ — план, а
не выполненная работа: каждое решение с пометкой **решение мейнтейнеров** нужно принять до начала.

## 1. Общие условия

- **Одна подпись.** Пользователь, поставивший APK из Releases, может обновиться только пакетом с тем
  же сертификатом. Каталог, который подписывает своим ключом (F-Droid по умолчанию, Google Play App
  Signing), даёт пакет, несовместимый с релизами GitHub. Варианты — воспроизводимая сборка с нашей
  подписью (F-Droid) или отдельный идентификатор пакета для каталога. **Решение мейнтейнеров.**
- **Сеть и данные.** Разрешений нет вообще (нет `INTERNET`), телеметрии нет, локальная статистика
  выключена по умолчанию и не покидает устройство. Это упрощает анкеты каталогов.
- **Лицензия.** AGPL-3.0 с дополнительными условиями по разделу 7 (атрибуция). Для F-Droid и Google
  Play препятствий нет; для App Store — см. §4.
- **Проверка перед каждым каталогом:** зелёный `ci`, `android`, `ios`; ручная проверка на
  устройствах по списку из §5.

## 2. F-Droid

1. **Метаданные** (`fdroiddata/metadata/org.arca.viewer.yml`): категории `Security`, `Reading`;
   `License: AGPL-3.0-only`; `SourceCode`/`IssueTracker` — `https://github.com/team-ph4r0s/arca`;
   описание RU/EN из README (без заявлений, которые код не подтверждает).
2. **Сборка без Gradle.** Рецепт F-Droid допускает собственные команды: `sudo` — Rust по
   `rust-toolchain.toml`, цели Android, NDK `27.3.13750724`, build-tools `36.0.0`; `build` —
   `tools/build-guest.sh`, `tools/android/build-native.sh`, `tools/android/build-apk.sh` с
   `ARCA_THROWAWAY_KEY=1` (подписывает F-Droid). Все зависимости — из `Cargo.lock`, сеть нужна только
   на шаге `cargo fetch` (`--locked`).
3. **Воспроизводимость.** Сборка уже детерминирована (`tools/check-reproducible.sh`, сверка
   неподписанного пакета в релизе). Если F-Droid воспроизводит наш APK байт в байт, можно указать
   `Binaries:` и `AllowedAPKSigningKeys: 3b3b819d…737e` — тогда F-Droid раздаёт пакет с нашей
   подписью, совместимый с GitHub Releases. **Решение мейнтейнеров.**
4. **Анти-функции:** нет (`NonFreeNet`, `Tracking`, `Ads`, `NonFreeDep` не применимы). Прибавка
   атрибуции (раздел 7 лицензии) не является анти-функцией, но её стоит упомянуть в описании.
5. **Обновления:** `AutoUpdateMode: Version`, `UpdateCheckMode: Tags ^v[0-9.]+$` — опирается на
   политику тегов из `docs/RELEASING.md`.

## 3. Google Play

1. **Формат.** Новые приложения публикуются как Android App Bundle (AAB). Сборка без Gradle
   дополняется шагом `bundletool build-bundle` из тех же скомпилированных ресурсов, DEX и нативных
   библиотек; проверка — `bundletool build-apks` + установка на устройства из §5.
2. **Подпись.** Play App Signing хранит ключ приложения у Google. Варианты: загрузить в Play наш
   постоянный ключ (тогда пакеты совместимы с GitHub Releases, но ключ передаётся Google) или
   отдельный ключ/идентификатор для Play. **Решение мейнтейнеров.**
3. **Data safety:** «данные не собираются и не передаются»; шифрование при передаче — не применимо
   (сети нет); удаление данных — локальная статистика удаляется в настройках.
4. **Политики:** целевой API — текущий (36); доступ к файлам — только через системный выбор
   файла и «Открыть с помощью»/«Поделиться», без широких разрешений; описание не обещает
   «100 % защиту».
5. **Тестирование:** внутренний трек → закрытый трек (не менее 12 тестировщиков 14 дней для новых
   личных аккаунтов разработчика) → продакшн.

## 4. App Store

1. **Лицензия.** AGPL и условия App Store (ограничения на распространение и использование)
   исторически считаются несовместимыми для чужого кода под GPL. Все авторы ядра — команда, поэтому
   возможна двойная лицензия или исключение для App Store. **Юридическое решение мейнтейнеров.**
2. **Экспортный контроль.** В ядре есть собственная криптография (расшифровка документов
   пользователя: AES, RC4, SHA, MD5). Значение `ITSAppUsesNonExemptEncryption` в
   `app/project.yml` и, при необходимости, годовой отчёт / CCATS определяют мейнтейнеры (обсуждение
   в #86). **Юридическое решение мейнтейнеров.**
3. **Изоляция.** На iOS нет отдельного процесса-песочницы (см. `docs/IOS_ARCHITECTURE.md`); в
   описании для App Review и в тексте приложения это не скрывается.
4. **Сборка и подпись:** Apple Developer Program, профиль распространения, архив Xcode из
   `app/project.yml` (XcodeGen 2.46.0), загрузка через Transporter или `xcrun altool`.
5. **TestFlight:** внутренние тестировщики → внешняя группа (проходит бета-ревью) → релиз.

## 5. Проверка на устройствах (перед каждым каталогом)

| платформа | устройства | что проверить |
|---|---|---|
| Android 8 (API 26) | эмулятор или старый телефон | запуск песочницы (изолированный процесс), открытие DOCX/PDF/XLSX |
| Android 14–16 | телефон, планшет, складной | лента страниц, «Поделиться», стерильная копия с паролем, тёмная тема |
| Android, клавиатура/DeX | планшет или ПК-режим | PageUp/PageDown, Ctrl +/− |
| iPhone, iPad (iOS 16+) | реальные устройства | открытие из «Файлов», ссылки, пароль, стерильная копия |

Набор документов: `tests/fixtures` и презентации пользователей (без личных данных).
